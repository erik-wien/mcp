# Publishing rules

Rules for what goes to GitHub when publishing any `~/Git/*` repository. Apply to every repo in this ecosystem (apps, libraries, infrastructure) before pushing to a public remote.

## Never publish

These paths must not be committed to any public (or private-but-shared) GitHub repository. If they are already tracked, `git rm --cached` them and add to `.gitignore`.

| Path / pattern | Reason |
|---|---|
| `CLAUDE.md` (any depth) | Personal / agent-workflow notes, not for other devs |
| `.claude/` (any depth) | Agent config, memory, session state |
| `~/.claude/...` | User-global agent state (not in repos to begin with, but double-check) |
| `docs/superpowers/` | Plan / spec drafts from agent-driven development |
| `update.md` | Per-deploy scratch pad written by `mcp/generate.py` |
| `config.yaml` | Per-target deploy config — contains DB passwords, FTP credentials |
| `.env`, `.env.*` | Local secrets |
| `data/`, `backups/`, `logs/`, `cache/` | Runtime state, user data |
| `.phpunit.result.cache` | Local test state |
| `.worktrees/`, `worktrees/` | Local git worktree scratch space |
| `jardyx-mail.ini`, `mail.ini` | SMTP credentials (host-level, never in repo) |

All of these belong in `.gitignore` (or are generated at deploy time).

## Safe to publish

- Source code (PHP, JS, CSS, SQL migrations, templates).
- `composer.json` / `composer.lock`, `package.json` / `package-lock.json`.
- `config.example.yaml` — redacted template generated by `mcp/generate.py`, safe to commit.
- `README.md`, `LICENSE`, `docs/` (excluding `docs/superpowers/`).
- `.gitignore`, `.htaccess`, `.editorconfig`.
- Error-page HTML (`web/error/*.html`) and error-page server snippets (`web/error/nginx.conf`).
- Fonts and icons shipped with a project (subject to font licence terms — Atkinson Hyperlegible is SIL-OFL).

## Convention docs

Rule content that is useful to other developers (design system, auth conventions) lives inside the relevant repo under `docs/`:

- Design system rules → `css/docs/design-rules.md`
- Auth library conventions → `auth/docs/conventions.md`
- Publishing rules → `mcp/rules/publishing.md` (this file)

Personal agent-workflow rules (written for a Claude session rather than a human contributor) stay in `~/.claude/rules/` and are never copied into a repo.

## Before pushing a new repo

Checklist:

1. `git ls-files | grep -E '^(CLAUDE\.md$|\.claude/|docs/superpowers/|update\.md$)'` — must be empty.
2. `cat .gitignore` — must cover every entry in the "Never publish" table above.
3. `git log --all -- CLAUDE.md .claude docs/superpowers update.md` — must be empty for *new* public repos; for already-public repos with a dirty history, rewrite with `git filter-repo --invert-paths --path CLAUDE.md --path .claude --path docs/superpowers --path update.md` before force-pushing.
4. `git grep -i 'password\s*=' -- '*.php' '*.yaml' '*.ini'` — verify no hardcoded credentials in source.
5. `gh repo view <user>/<repo> --json visibility` — confirm the visibility you expect before the first push.
